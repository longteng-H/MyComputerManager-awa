## 排查：单文件版双击后无法运行

### 根因（已确证）

`MyComputerManager-单文件.exe` 启动即崩溃，Windows 事件日志（.NET Runtime / Application Error）：

```
异常信息: System.Exception
   在 System.Windows.Application.LoadComponent(System.Object, System.Uri)
   在 MyComputerManager.App.InitializeComponent()
   在 MyComputerManager.App.Main()
```

用反射读取该 exe 的元数据（安全，不执行代码）：

| 项目 | 正常版 | 单文件版 |
|---|---|---|
| 程序集名 | `MyComputerManager` | **`MyComputerManager-merged`** |
| 引用程序集数 | 16（含 Wpf.Ui、Microsoft.Extensions.*） | 10（只剩框架程序集） |
| 资源数 | 2 | 72（含 `Wpf.Ui.g.resources`、27 个 `ILLink.Substitutions.xml`） |

结论：该文件是用 **ILMerge 3.0.41** 把所有依赖合并进主程序集生成的（无 `costura.*` 资源，依赖被真正合并而非嵌入），且 ILMerge 把输出程序集名改成了 `/out` 指定的文件名。

而 WPF 在编译期已把 pack URI 硬编码进生成的代码（`obj\Release\App.g.cs:60`）：

```csharp
System.Uri resourceLocater = new System.Uri("/MyComputerManager;component/app.xaml", System.UriKind.Relative);
```

运行时程序集实际叫 `MyComputerManager-merged`，找不到名为 `MyComputerManager` 的程序集 → `LoadComponent` 抛异常 → 进程终止，双击表现为“毫无反应”。注意 `MyComputerManager.g.resources` **确实在**合并结果里（第 84 项），所以问题不在资源丢失，而在程序集名不匹配。

附加证据：`Wpf.Ui.dll` 内部有 2 处 `Wpf.Ui;component` 字符串，即它同样用 pack URI 引用自身资源。**因此即使把 `/out` 改成 `MyComputerManager.exe` 让主程序集名对上，Wpf.Ui 的 URI 依旧会失效 —— ILMerge 对本项目整体不可行。**

### 第二处缺陷：Costura 配置一直处于“静默失效”状态

项目原本就想用 Costura 做单文件：`FodyWeavers.xml` 已有 `<Costura />`，csproj 也写了

```xml
<Import Project="..\packages\Fody.6.9.3\build\Fody.targets" Condition="Exists('..\packages\Fody.6.9.3\build\Fody.targets')" />
```

但 `packages\` 下的目录是无版本号的 `Fody\`、`Costura.Fody\`，`Exists()` 判定为 false → **导入被静默跳过，Fody/Costura 从未运行**。`packages.config` 里也没有这两个包。这就是为什么用户绕过构建系统、手工跑了 ILMerge。

### 修复（已完成）

1. 规范包目录：`packages\Fody` → `packages\Fody.6.9.3`、`packages\Costura.Fody` → `packages\Costura.Fody.6.2.0`
2. csproj 顶部导入 `Costura.Fody.props`（它负责注册 `WeaverFiles`，缺它 Fody 找不到 weaver）
3. csproj 底部新增 `Costura.Fody.targets` 导入，修正 `Fody.targets` 路径
4. `EnsureNuGetPackageBuildImports` 增加 3 条 `<Error>` 守卫 —— 缺包时**显式报错**，杜绝再次静默失效
5. `packages.config` 登记 `Fody 6.9.3`、`Costura.Fody 6.2.0`（developmentDependency）
6. README 增加「单文件发布」小节，明确禁止用 ILMerge 打包 WPF

### 验证

- 反射校验 weaver 解析链：props → `packages\Costura.Fody.6.2.0\netclassicweaver\Costura.Fody.dll` 存在 ✓
- csproj / packages.config XML 合法；4 条包导入路径全部可解析 ✓
- packages.config 46 个包与 packages/ 目录一一对应 ✓

### 交付：`build.ps1` + `build.bat`

新增根目录 `build.ps1`（约 15.5 KB，UTF-8 **带 BOM**，以便 PS 5.1 正确读中文）与 `build.bat`（纯 ASCII，规避 cmd.exe 代码页乱码；用 `%~dp0` 推导路径，兼容含中文的安装路径）。

脚本 5 步：预检包 → 定位 MSBuild（vswhere → 路径扫描 → PATH）→ Release Rebuild → **校验产物** → 复制到 `dist\`。校验三条硬性规则：

1. 程序集名必须是 `MyComputerManager`（防 ILMerge 改名重现）
2. 必须存在 `costura.*` 内嵌资源，且覆盖 38 个预期依赖（正则 `^costura\.<name>\.dll(\.compressed)?$`，兼容 Costura 默认压缩）
3. 输出目录不得残留任何依赖 DLL

`-SmokeTest` 开关：把 exe 单独复制到临时空目录启动，6 秒内未退出即判定自包含成立。

### 重要发现：分发实际是「两个文件」

`MyComputerManager.exe.config` 含 4 条真实 `bindingRedirect`（System.Drawing.Common、System.Runtime.CompilerServices.Unsafe、Microsoft.Extensions.Configuration.EnvironmentVariables、.UserSecrets），由 NuGet 自动生成，**不能省**。所以「单文件」严格来说是 exe + exe.config。脚本已把两者一并复制到 `dist\`。
